# 指標定義

このダッシュボードで使用しているすべての指標の定義。
同じ名前の指標が画面ごとに違う意味を持つことを防ぐため、定義はここに一元化する。

---

## 1. 共通の前提

| 項目 | 定義 | 理由 |
|---|---|---|
| **分析基準日** | `LEAST(データ最大日, 実行日 - 1日)` | ビュー `v_config` で一元管理。元データに未来日付が含まれうること、当日分が部分データであることの両方に対応する |
| **売上の対象** | `order_items` のうち `status` が `Cancelled` / `Returned` 以外の行 | 金額は明細にしか存在せず、キャンセルは商品単位で発生するため、注文単位ではなく明細単位で除外する |
| **通貨** | USD | 元データ `thelook_ecommerce` の単位 |

---

## 2. 売上・注文系

| 指標 | 式 | 粒度 | BIでの集計 |
|---|---|---|---|
| 売上（revenue） | `SUM(sale_price)` | 任意 | 合計 |
| 粗利（profit） | `SUM(sale_price - cost)` | 任意 | 合計 |
| 注文数（orders） | `COUNT(DISTINCT order_id)` | 任意 | 合計 |
| 購入者数（buyers） | `COUNT(DISTINCT user_id)` | 任意 | 合計 |
| 平均注文単価（avg_order_value） | `売上 ÷ 注文数` | 1日 | **平均** |
| 7日移動平均（revenue_ma7） | `AVG(revenue) OVER (ORDER BY order_date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)` | 1日 | **平均** |
| 28日移動平均（revenue_ma28） | 同上（27 PRECEDING） | 1日 | **平均** |
| 前年同日比（yoy_percent） | `revenue ÷ LAG(revenue, 365) × 100` | 1日 | **平均** |

> 移動平均と前年比は、日付が連続しているテーブル（`mart_daily_sales`）の上で計算している。
> 注文のない日が行ごと消えると、`ROWS BETWEEN` や `LAG` の窓がずれるため。

## 3. RFM

| 指標 | 定義 | BIでの集計 |
|---|---|---|
| recency_days | 分析基準日 − 最終購買日（日数） | **平均** |
| frequency | 注文回数（`COUNT(DISTINCT order_id)`） | 合計 |
| monetary | 累計売上 | 合計 |
| r_score | `NTILE(5)` を recency_days の**昇順**で付与（直近ほど5） | ディメンション |
| f_score | `NTILE(5)` を frequency の**降順**で付与（多いほど5） | ディメンション |
| m_score | `NTILE(5)` を monetary の**降順**で付与（高いほど5） | ディメンション |
| user_share | セグメント人数 ÷ 全体人数 × 100 | **平均** |
| revenue_share | セグメント売上 ÷ 全体売上 × 100 | **平均** |

**セグメントの境界**：`NTILE(5)` による5分位。絶対値ではなく相対順位で切っているため、
データが増減しても各セグメントの人数構成比は概ね一定に保たれる。

## 4. コホート定着

| 指標 | 定義 | BIでの集計 |
|---|---|---|
| cohort_month | 初回購買日を月初に丸めた値 | ディメンション |
| month_index | 獲得月からの経過月数（0 = 獲得月） | ディメンション |
| cohort_users | そのコホートの顧客数（分母） | 合計 |
| active_users | その月に購買があった人数 | 合計 |
| retention_rate | `active_users ÷ cohort_users × 100` | **平均** |
| simple_avg_retention | 各コホートの定着率の単純平均 | **平均** |
| weighted_avg_retention | `SUM(active_users) ÷ SUM(cohort_users) × 100`（人数で重み付け） | **平均** |
| arpu | その月の売上 ÷ active_users | **平均** |

**除外条件**：まだ到来していない月は行を生成しない。進行中の月も除外する
（月の途中の実績を1ヶ月分として扱うと直近の値だけが下振れするため）。

**0の扱い**：経過済みだが購買がゼロだった月は `0%` として算入する。
行が存在しないことと値が0であることは意味が異なり、補完しないと
その月が平均の分母から消えて定着率が過大に算出される。

## 5. LTV

| 指標 | 定義 | BIでの集計 |
|---|---|---|
| days_elapsed | 初回購買からの経過日数（30 / 60 / 90 / 180 / 365） | ディメンション |
| avg_ltv | 経過日数時点の累計売上の平均 | **平均** |
| median_ltv | 同じく中央値 | **平均** |
| target_users | 集計対象となった顧客数 | 合計 |

**公平な比較のための条件**：各マイルストーンは「その日数が経過済みの顧客のみ」を対象とする。
経過していない顧客を0円として含めると、直近に獲得したチャネルほどLTVが低く見える。

**表示上の除外**：`target_users >= 30` 未満のセグメントは非表示。母数が小さいと平均が不安定になる。

**平均と中央値の併記**：LTVは一部の高額顧客によって分布が右に歪むため、平均のみでは実態を過大評価する。

## 6. バスケット分析

| 指標 | 式 | 意味 | BIでの集計 |
|---|---|---|---|
| pair_count | 2品が同じ注文に含まれた注文数 | 同時購入の実数 | 合計 |
| support | `pair_count ÷ 全注文数 × 100` | 全注文に占める割合 | **平均** |
| confidence (A→B) | `pair_count ÷ Aを含む注文数 × 100` | Aを買った人がBも買う確率 | **平均** |
| lift | `confidence ÷ (Bの出現率)` | 偶然と比べて何倍一緒に買われるか | **平均** |

**リフト値の読み方**

| 値 | 意味 |
|---|---|
| 1.0 | 無関係（偶然どおり） |
| 1.0 超 | 一緒に買われやすい |
| 1.0 未満 | むしろ一緒に買われにくい |

**強調の閾値**：`lift > 1.5`。1.0を超えていれば正の関連ではあるが、1.0付近は
誤差の範囲に入りやすいため余裕を持たせている。

**ノイズ除去**：カテゴリ単位は `pair_count >= 30`、商品単位は `pair_count >= 5` 未満のペアを除外。

## 7. ABC分析

| 指標 | 定義 | BIでの集計 |
|---|---|---|
| revenue | 商品ごとの売上合計 | 合計 |
| rank_no | 売上降順の順位 | ディメンション |
| cumulative_share | 売上降順に積み上げた累積構成比（%） | **平均** |
| abc_rank | A: 累積70%まで／B: 90%まで／C: それ以降 | ディメンション |

## 8. セッション・ファネル

**セッションの定義**：同一ユーザーの行動ログを時系列に並べ、**30分以上の間隔が空いた時点**で
別セッションとして区切る（gaps-and-islands法による自前実装）。
元データの `session_id` とは独立に定義し、両者を照合して差分を検証している。

| 指標 | 定義 | BIでの集計 |
|---|---|---|
| sessions | セッション数 | 合計 |
| duration_sec | セッションの継続秒数 | **平均** |
| event_count | セッション内のイベント数 | **平均** |
| overall_rate | `sessions ÷ 最初のステップのsessions × 100` | **平均** |
| step_rate | `sessions ÷ 直前のステップのsessions × 100` | **平均** |
| drop_rate | `100 − step_rate` | **平均** |
| dropped_sessions | 直前のステップとの差（実数） | 合計 |
| cvr | `購入到達セッション ÷ 全セッション × 100` | **平均** |

**ファネルの5ステップ**

1. セッション開始
2. カテゴリ閲覧
3. 商品詳細閲覧
4. カート投入
5. 購入完了

**流入元の定義**：`entry_traffic_source`（セッション開始時点の流入元）。
セッション途中で変化しうる値を使うと、1セッションがどのチャネルに属するかが一意に決まらない。

---

## 9. BIでの集計方法に関する注意

比率は加算できない。以下に該当する指標は、Looker Studio で配置するたびに
集計方法を**「平均」**に変更すること。既定は「合計」であり、そのままにすると
通過率が100%を超えるなどの不正な値になる。

- `〜_rate` / `〜_share` / `cumulative_share`
- `lift` / `confidence_〜` / `support_〜`
- `avg_〜` / `median_〜`
- `cvr` / `yoy_percent`

実数（件数・人数・金額）は「合計」のままで正しい。
